# portfolio

Karolina Kita's portfolio (karolina.kita.company), public repo github.com/karolinakita-ux/portfolio. React 19 + TypeScript (strict) + Tailwind v4 on Vite, tested with Vitest + Testing Library and Playwright, work on `develop`, deployed by Netlify from `main` on release. Package manager: **yarn** (v1). Dev machine: Windows 11, Node via fnm (`.node-version`).

## Commands

- `yarn dev` - local server at http://localhost:5173
- `yarn verify` - typecheck, lint (zero warnings), Prettier check, tests, production build. Run before every commit.
- `yarn test` - Vitest in watch mode; `yarn test:run` once
- `yarn e2e` - Playwright tests (`e2e/*.e2e.ts`) in Chromium, Firefox and WebKit against a fresh production build with prerendered pages on 127.0.0.1:5190. Run it after UI, motion or theme changes; it is not part of `yarn verify` or the Netlify build. `E2E_DEV=1 yarn e2e` tests the dev server; `--project chromium` or a spec name (`yarn e2e header-motion`) narrows a run. One run at a time (shared port and `test-results/`; `E2E_PORT` picks another port). First time: `yarn playwright install chromium firefox webkit`.
- `yarn storybook` - the component library at http://localhost:6006; `yarn build-storybook` builds it into `dist/storybook` (run after `yarn build`, which empties `dist/`)
- `yarn typecheck`, `yarn lint`, `yarn format` (writes), `yarn format:check`
- `yarn favicons` - remakes `favicon.ico`, `favicon-96x96.png` and `apple-touch-icon.png` in `public/` from `public/favicon.svg` (sharp). Run it after changing the SVG and commit the files.
- `yarn cv-pdf` - remakes `public/karolina-kita-cv.pdf` from the /cv page (a build in `node_modules/.tmp/cv-pdf`, Playwright Chromium, tagged A4, at most 2 pages) and `scripts/cv-pdf.lock.json`. Run it after changing the CV's content or styles and commit both files; `src/app/seo/cv-pdf.test.tsx` fails when the CV's text, markup or classes changed without it. It cannot see a change in `tokens.css` or `print.css`: run it by hand after one that reaches the CV. Each run writes a new file (Chromium dates it), so run it only when the CV changed.

## Layout

Vertical slices: `app` → `features` → `shared`, never the other way.

- `src/app/` - the shell: `App/` (`App.constants.tsx` maps every `View` to its feature's view), `routing/` (`useHistoryRoute.ts`: real paths, old `/#view` links redirect; `useSectionHash.ts`: the hash follows the section in view, except in in-app browsers; nothing else writes to the history while scrolling, because in-app browsers such as Messenger and LinkedIn flash a loading bar on every write; in-app browsers also switch the theme without the view-transition cross-fade (`changeTheme`, `shared/hooks/theme/theme.utils.ts`); `useRouteFocus.ts`; a section link's first load is landed and held by the inline script in `index.html` before the app loads, until the visitor's first touch, and the app then only moves focus: `data-kb-anchor-held`, docs/architecture.md Routing), `seo/` (`seo.content.ts` descriptions, `seo.utils.ts` head tags, structured data, llms.txt; `useDocumentHead.ts`), `analytics/` (pageviews), `hydration/` (whether `main.tsx` adopts the prerendered HTML; `hydration.test.tsx` hydrates every page), `prerender.entry.tsx`, `content-rules.test.ts` cross-feature copy checks.
- `src/features/<name>/` - one slice per page or capability: `work`, `about`, `contact`, `cv` (the CV page; the PDF is printed from it), `case-studies`, `image-viewer`, `privacy` (the policy page and the statistics consent box), `accessibility` (the accessibility statement: keep it true to the code when a WCAG-related behaviour changes). A slice owns its view, components, hooks, copy (`*.content.ts`), types (`*.types.ts`) and tests. The app imports a feature only through its `index.ts`; features never import each other. Most copy edits happen in `*.content.ts`.
- `src/shared/` - used by several slices: `ui/` primitives (`ProseSection`: a text page's section, used by the privacy policy and the accessibility statement), `layout/` header/footer, `media/` images, preload and the viewer context, `hooks/`, `lib/` (one folder per domain: `routes/` with `VIEW` ids, `VIEW_PATHS`, `SECTION` anchors, page titles and URL helpers; `ui/` with the shared class lists `FOCUS_RING`, `TEXT_LINK`, `BUTTON_HEIGHT`, `BULLET_LIST` and `EXTERNAL_LINK`; `analytics/`, `motion/`, `clipboard/`), `content/profile.ts`. Shared code never imports `app` or `features`.
- Repeated values (view ids, paths, section anchors, storage keys) are `as const` objects with a derived union type, never `enum` (`erasableSyntaxOnly`) and never repeated string literals.
- Every `Section` heading gets a copy-link anchor (`HeadingAnchor`); its `id` is the URL hash. So does a titled `Callout` given an `id` (the Behind the Design banner, `/#behind-the-design`). Keep section ids stable: they are shared links, and they never take a view's name (`/#about` opens About).
- Imports: `#app/*`, `#features/*`, `#shared/*`, `#test/*` (subpath imports in `package.json`); `./x` within the same folder or below it; never `../`. A slice imports its own files across folders as `#features/<slice>/...`, never another slice's (ESLint, regex patterns).
- Files and folders (details and an example tree: `docs/architecture.md`, Files and folders): one component per folder, `Button/Button.tsx` + `Button.types.ts` (props) + `Button.styles.ts` (all its classes) + `Button.test.tsx`; one folder per domain for other modules (`lib/routes/routes.constants.ts`, `.types.ts`, `.utils.ts`); hooks `useX.ts`; other modules kebab-case with a role suffix (`*.content.ts`, `*.types.ts`, `*.styles.ts`, `*.constants.ts`, `*.context.ts`, `*.utils.ts`), except inside a component folder, where they take the component's name (`Dialog.utils.ts`, `CaseNavLink.constants.ts`). No per-component barrel `index.ts`; only a feature's `index.ts` (its public API). ESLint caps files at 200 lines of code (tests and copy excepted).
- `e2e/` - Playwright specs (`*.e2e.ts`) and `helpers/` (in-page toolkit with the frame sampler and pill animation log, page setup, motion expectations), type-checked by `tsconfig.e2e.json`. Vitest only collects `src/**/*.test.ts(x)`.
- `scripts/` - `prerender.ts`, `a11y-audit.ts` (checks in `scripts/a11y/`), `favicons.ts`, `cv-pdf.ts` (with `cv-pdf.lock.json`).
- `.storybook/` - Storybook: `main.ts` (stories, addons, the one image folder the stories use), `preview.tsx` (site CSS and fonts, light/dark toolbar, axe as an error), `*-head.html` (noindex). Listed by name in `tsconfig.app.json`: `tsc` skips dot folders in `include` globs.
- `src/styles/tokens.css` - KitaBranding tokens as CSS variables (light + dark); `theme.css` maps them into Tailwind's theme; `app.css` imports both plus `utilities.css`, `base.css`, `dialog.css`, `lightbox.css`, `motion.css`, `print.css`. Test and story files are excluded from Tailwind's class scan (`@source not`).
- `src/styles/kita-branding.tokens.json` - Figma Variables export; `tokens.test.ts` keeps `tokens.css` 1:1 with it.
- `public/assets/` - images: `site/` (portrait, link-preview image `og-cover.png`: the Light "Portfolio Cover" from Figma, light only because previews cannot follow the viewer's theme; `docs/design.md`) and `cases/<case>/` (screenshots, `thumbnail-light.webp` and `thumbnail-dark.webp`), referenced from content by their path under `/assets` (`cases/project-planning/thumbnail-light.webp`). Case screenshot cards come from `caseShots(folder)` (`features/case-studies/content/content.utils.ts`): `shot()` for a Light/Dark pair (`<name>-light.webp` / `-dark.webp`), `singleShot()` for one file; the card id is the image's base name (the statistics' `image` value). Lowercase kebab-case. Screenshots are WebP (`sharp`, quality 90); the link-preview image stays PNG. No `srcset` on lazy images: WebKit then loads them eagerly and they hold up the page's load event (checked 2026-10-20). `/assets/*` is cached for a week, so a changed image gets a new file name. Case images keep their content out of the hover zoom's band (about 1% of each edge, 2% for frameless images and thumbnails): pad the file, never scale it (`src/app/zoom-margins.test.ts`).
- `public/favicon.svg` - the site icon. Google Search does not read SVG favicons (it lists BMP, GIF, ICO, PNG, JPEG, PPM and TIFF) and shows a plain globe without another icon, so `index.html` links the copies `yarn favicons` makes after the SVG: `favicon-96x96.png`, `favicon.ico` (16, 32, 48 px) and `apple-touch-icon.png` (180 px, no transparency). The names never change (Google asks for stable favicon URLs), so `_headers` caches them for a day only, and never with `X-Robots-Tag`. `src/app/seo/favicons.test.ts` checks the links, files and headers; `scripts/prerender.ts` fails the build when a page loses an icon link.
- `public/karolina-kita-cv.pdf` - the CV as a PDF, made by `yarn cv-pdf` and committed (`.gitignore` excludes every other PDF). Recruiters save its address, so the name never changes; `_headers` revalidates it on every visit and points search engines at `/cv` (canonical link). The Download labels say its page count (`PROFILE.cvPdfPages`, built once by `cvPdfLabel` in `shared/content/profile.utils.ts`). No phone number or street address on the CV.
- `docs/` - public project docs (design source, Figma links, the motion guide `motion.md`). Files and folders whose name starts with `_` (`docs/_*`) are private local notes: gitignored, never commit, quote or publish them.

## Design tokens (strict)

- Style only with token utilities: `bg-bg-canvas`, `text-text-secondary`, `border-border-subtle`, spacing `p-md` / `gap-lg` (3xs 2px … 4xl 96px), radius `rounded-sm|md|lg|xl|full`, shadows `shadow-sm…xl`, type `text-display-*`, `text-headline-*`, `text-title-*`, `text-label-*`, `text-body-*`.
- `theme.css` resets Tailwind's default colours, radii, shadows and font sizes, so `bg-gray-100` or `text-lg` do not exist. Never add hex values or arbitrary values where a token exists.
- Sizes follow the browser's text size: `theme.css` writes Figma's px as rem (px / 16) for breakpoints, spacing, type and layout widths, and icons turn their `size` into rem. At the default 16px everything matches Figma to the pixel; when a visitor sets a larger text size, the page grows as with zoom. Only radius, shadows and motion offsets stay in px (`src/styles/relative-units.test.ts`); `yarn a11y` checks every page at 200% text. Long words break only where they do not fit (`overflow-wrap` in `base.css`).
- Dark mode swaps CSS variables via `.dark` on `<html>`. Do not use `dark:` variants.
- Motion (the guide, with every motion on the site and the test that guards it: `docs/motion.md`): `duration-fast|medium|slow` (150 / 240 / 300ms) and `ease-standard`, from the `--motion-*` tokens. Never `duration-150`, `ease-out` or a raw ms value, never Tailwind's `animate-spin|ping|bounce|pulse` (reset in `theme.css`) or anything `infinite` (`src/styles/motion-tokens.test.ts`); a named animation is an `--animate-*` in `theme.css` that ends within 5 s, an entrance filling `backwards` (`animations.test.ts`). Motion stays calm: nothing moves on the first screen at load, nothing loops past 5 s, and `prefers-reduced-motion` makes every change instant (the CSS rule in `motion.css`; animations started from JS check `prefersReducedMotion()`). The scroll reveal is on card lists from md up, never on phones, and a case page's closing sections after its impact stay still (Karolina's rule). Smooth scrolling only for a jump within the page, never across a view change.
- Figma is the design source (Karolina, 2026-10-30): a design change starts in Figma or is mirrored there the same day, so the Figma file and `develop` agree (the live site follows at the next release). When they differ and nobody has decided, ask Karolina; never let one side win silently. Figma uses only the Kita Branding variables: no values from other libraries, no new custom colours. Details: `docs/design.md`.
- New token: add it in Figma, re-export `kita-branding.tokens.json`, then add the variable to `tokens.css` (both modes; motion tokens once, they have no mode) and the mapping in `theme.css`. Mirror it in the KitaBranding design system on claude.ai.
- More contrast: the Figma modes "Light more contrast" and "Dark more contrast" apply when the visitor's system asks for it (`@media (prefers-contrast: more)` at the end of `tokens.css`, only the tokens that change). Reading text reaches 7:1 and borders and focus rings 3:1 there (`contrast.test.ts`); `e2e/contrast.e2e.ts` checks that browsers apply it. A new text, border or status token gets values in those modes too. Windows contrast themes use forced colours instead: focus styles are outlines, never box shadows alone (`yarn a11y` checks every Tab stop in forced colours).
- WCAG 2.2 AA minimum: keyboard focus (`FOCUS_RING`), labelled controls, semantic headings and landmarks. Nothing fixed or sticky may hide the focused element (2.4.11): the header publishes `--kb-header-h` and the consent box `--kb-consent-h` (`useConsentSpace`) for the scroll padding in `base.css`, and `yarn a11y` hit-tests every Tab stop, also with the consent box showing. The header's own links and buttons are exempt from that padding (`scroll-margin` on `.kb-site-header` in `base.css`), so Tab inside the stuck header never scrolls the page (`e2e/header-layout.e2e.ts`, also with the consent box's space). A control's accessible name starts with its visible label (2.5.3). A state is never shown by the yellow marker alone (1.54:1 on white).
- A row of text links that can wrap (the Behind the Design banner) is spaced like buttons: each link gets `BUTTON_HEIGHT` (`shared/lib/ui/ui.styles.ts`: a bordered Button's height) and the row `gap-y-sm`. Karolina's rule: tighter rows look cramped.
- On focusable elements, list the transitioned properties (`transition-[color,background-color]`, as `Button.styles.ts` does). `transition-colors` also animates `outline-color`, so the focus ring would fade in instead of appearing at once (`e2e/motion-a11y.e2e.ts` checks it).

## Copy rules (Karolina's, enforced by `src/app/content-rules.test.ts`)

- Short hyphen with spaces (`word - word`, `2019 - 2026`). Never en or em dashes.
- Every case-study bullet opens with a bold lead-in and colon: build bullets with `lead("Term", "text")` from `shared/ui/lead/lead.tsx`.
- H1 headings never end with a period.
- Headings are in Title Case (Karolina, 2026-10-30): H1 to H4, card, banner and box titles, FAQ questions, eyebrows and detail labels ("My Role"). Every word starts with a capital except articles, conjunctions and prepositions of up to 4 letters inside it (`a`, `and`, `of`, `with`, `from`, `vs.`); the first and last word and the word after a colon or a spaced hyphen always do ("Why - The Standard", "Goals & Milestones Timeline (Proposal)"). Screenshot captions keep their Figma frame names. `content-rules.test.ts` renders every page and checks each heading (`src/test/copy-rules.ts`).

Quotes stay verbatim: real people's words, names ("Harbor Bank") and product labels as a screenshot shows them ("Duplicate to customize"). ## Code conventions

- TypeScript strict with `noUncheckedIndexedAccess`; no `any`. Import with explicit extensions (`./App.tsx`), `import type` for types.
- Files that export components export only components (Fast Refresh); helpers live in `*.utils.ts`, constants in `*.constants.ts`, types in `*.types.ts`, contexts in `*.context.ts`.
- Classes: a component's Tailwind classes live in its `*.styles.ts` as a `styles` object (one key per element; state-dependent ones are functions, `styles.pill(active)`), composed with `clsx` (object syntax for toggles: `clsx("...", { "rotate-180": open })`). Variant sets use `cva` with the variant names from Figma (`button({ variant })`, `callout({ tone })`, `card({ layout, gap })`). Prettier sorts classes inside `clsx()` and `cva()`. ESLint rejects class strings inside `className`; compute state before the JSX (`const loaded = status === "loaded"`) rather than in the attribute. No `tailwind-merge`: it reads token type styles as colours and drops them (`text-body-md` vs `text-text-primary`), so give conflicting classes a variant instead.
- Library first: before writing markup, use the `shared/ui` primitive that exists (`Card`, `Badge`, `PageTitle`, `Button`, `IconButton`, `Callout`, `Section`, `Dialog`, `Accordion`/`AccordionItem`, `Avatar`, `VisuallyHidden`, `NewTabNote`, `Breadcrumb`, `CopyEmail`). External links spread `EXTERNAL_LINK` and end with `<NewTabNote />`.
- ESLint: typescript-eslint `strictTypeChecked` + `stylisticTypeChecked`, `@eslint-react`, `jsx-a11y`, Vitest + Testing Library rules, and the slice boundaries (`no-restricted-imports` with `regex` patterns: in gitignore-style `group` patterns a leading `#` is a comment, which once switched the boundaries off unnoticed). Fix the code rather than disabling a rule; a needed exception is a one-line disable with a reason after `--`. Prettier sorts imports by layer.
- Visitor statistics (Umami) are opt-in: the script loads only after the visitor allows it in the consent box or on /privacy (`shared/lib/analytics/statistics-consent.utils.ts`; ePrivacy Art. 5(3) and Art. 399 of Prawo komunikacji elektronicznej need consent for a script that reads device data, cookies or not). New events go through `track()`; never load a tracker any other way. The tracking plan `docs/analytics.md` holds the naming rules (kebab-case `<object>-<verb>` for actions, noun phrases for measurements, context in properties) and a row per event and session property (`tracking-plan.test.ts`). Links the site writes itself carry a link tag from `LINK_REF` (`analytics.constants.ts`): `?ref=cv` on the CV PDF's portfolio link, `?ref=section-link` on a section link copied with `HeadingAnchor` (`sharedSectionUrl`: the page's path, the tag and the anchor, never the copier's own query); the plan's Tagged links table lists each one. Address changes that are not a new page use `replaceAddress()` (`shared/lib/routes/address.utils.ts`), never `history.replaceState` with a URL: the tracker's speed report takes each one as a new page. `umami.identify()` gets session data only, never an id. Each event needs a line in the privacy policy; a new kind of data (not one more click of a kind already listed) also bumps `STORED_CHOICE.on` in `analytics.constants.ts`, so earlier yeses are asked again, and goes into the consent box text. On `yarn dev` the consent box shows on every page load to check its design (`consentPreview`; an answer hides it until reload, nothing loads); automated browsers (`navigator.webdriver`: e2e, `yarn a11y`) do not get it.
- Elements that sit side by side (flex items, spans set to block, a link after text) get a space between them in the markup (`{" "}`, not rendered between flex items): without CSS, search engines, AI assistants and plain-text copies read "Next Case StudyEnterprise". `src/app/plain-text.test.tsx` checks every page.
- The browser adopts the prerendered HTML (`hydrateRoot` in `src/main.tsx`), so a component's first render must match it in Light and Dark: what only the browser knows (storage, `matchMedia`, the user agent, the date) comes through `useSyncExternalStore` with a server snapshot, or waits for `useHydrating()` (`shared/hooks/hydration/`). Build-time values (the footer's `APP_BUILD_YEAR`) are `define`s in `vite.config.ts`. `src/app/hydration/hydration.test.tsx` fails on any hydration warning (`docs/architecture.md`, Rendering and SEO).
- React Compiler lint rules are on: no `setState` inside effects, no ref reads during render. Derive state instead (see `useImageStatus`, `useScrolledPast`). An object returned by a hook that holds a ref counts as a ref: destructure it (`const { status, setImage } = useRevealedImage(src)`).
- Tests sit next to the code (`*.test.ts(x)`); query by role and accessible name. jsdom gaps are polyfilled in `src/test/setup.ts`.
- Stories: every component folder in `shared/ui`, `shared/layout` and `shared/media` has a `Name.stories.tsx` (a small sibling may be shown in another's story: `COVERED_ELSEWHERE` in `src/test/stories.test.tsx`). That test runs every story in Vitest (render, its `play` checks, axe) and fails when a component has no story. Import `userEvent` and `expect` from `storybook/test`; give stories real copy from the site.
- Line endings are LF (`.gitattributes`). Netlify builds on Linux, so file names are case-sensitive.

## Git workflow (full process: `CONTRIBUTING.md`)

- Work on `develop`. Never commit or push to `main` except in a release the user asked for.
- Every commit: `yarn verify`, bump `version` in `package.json` (semver rules in `CONTRIBUTING.md`), add a `###` entry under `## Unreleased` in `CHANGELOG.md`, all in the same commit. Put the version in the subject: `... (1.2.0)`.
- Stage files by name, only the ones you changed. Never `git add -A` or `git commit -a`: the user often has unfinished edits in the tree. Check `git status` before committing and leave anything you did not write unstaged.
- Engineering commits (structure, refactors, tooling, libraries) carry `Co-authored-by: Mateusz Kita <mkita.webdev@gmail.com>` beside the Claude trailer (`CONTRIBUTING.md`).

### Skills and agents (`.claude/`)

- `release` (`.claude/skills/release/`): the release, only when the user asks for one. Compare against `origin/main`, not local `main`.
- `ship-change` (`.claude/skills/ship-change/`): the commit routine above, step by step.
- More skills: `add-tracking` (statistics events and session data), `update-dependencies`, `sync-design-system` (Figma, tokens, components, the claude.ai design system), `record-rule` ("remember ..."). `local-*` skills are personal and gitignored.
- Agents, all report only: `a11y-reviewer` (WCAG 2.2 AA), `ui-reviewer` (design system and UX, phone and desktop), `copy-reviewer` (Karolina's copy rules), `docs-seo-reviewer`, `confidentiality-reviewer`, `pattern-sweeper` (the same root cause elsewhere). When to use each: CONTRIBUTING.md (Claude Code helpers).

Uncommitted user edits stay out of commits and releases. If `git switch` refuses because of them, stop and ask; do not stash or discard them.

## Deploy

Netlify project `karolina-kita` builds and deploys only `main` (releases only). Pushes to `develop` and pull requests never build or deploy anywhere: the project deploys only the production branch with no Deploy Previews, and the `ignore` command in `netlify.toml` stops any other build. The build runs `yarn test:run && yarn build && yarn build-storybook` and publishes `dist/` (see `netlify.toml`). The CV's PDF is committed, not built: Netlify publishes `public/karolina-kita-cv.pdf` as it is (`yarn cv-pdf` makes it locally). `yarn build` ends with `yarn prerender`: an SSR build of `src/app/prerender.entry.tsx` and `scripts/prerender.ts`, which writes static HTML per page (`about.html` + `about/index.html`), `404.html` and `llms.txt`. A new view needs its path in `VIEW_PATHS`, a description in `seo.content.ts` and a line in `public/sitemap.xml`; tests check all three. When a page's visible content or its structured data changes, set its `<lastmod>` in the sitemap to the release date (Google trusts the dates only while they stay accurate). The footer's version number (`import.meta.env.APP_VERSION`, linked to `CHANGELOG.md` on main) does not count: it changes on every page with every release, like a copyright year. Hashed bundles go to `/static/` (cached for a year by `public/_headers`). Storybook is served at `/storybook/` with `X-Robots-Tag: noindex`; the Behind the Design banner on the Work page links it (`PROFILE.storybookUrl`: absolute in builds, so local previews and the artifact reach the live one; on `yarn dev` it is the local `yarn storybook` on port 6006), and its bundles never load on the site's pages. `public/googlecf978c6093e1d8a5.html` is Google Search Console's ownership file (HTML file method, property `https://karolina.kita.company/`): Google rechecks it, so never remove, rename or edit it (`src/app/seo/site-verification.test.ts` fails if it changes; `_headers` keeps it out of search results). A preview opened before a deploy reloads once when its story files are gone (`vite:preloadError` in `.storybook/preview-head.html`).

## Pitfalls (learned; details in Claude's local lessons log)

- Write files that contain backslashes (regexes, `\n` in strings) with the Write or Edit tool, or `String.raw` in JS. Bash heredocs on this Windows machine have silently eaten backslashes or failed to parse several times.
- Prove a new guard (lint rule, test) works: one probe that must fail and one that must pass, in NEW temporary files deleted afterwards, never edits to real files. No `|| true` after a restore step.
- Before wrapping a third-party script or library, read its current source for what each option does (the Umami tracker keeps a stale URL when its auto-tracking is off).
- Releases compare against `origin/main` after `git fetch`, and a deploy counts only when Netlify's current deploy points at the release commit (the Netlify MCP, then `curl` the live site).
- Check that a running dev or preview server serves the change before measuring; start your own on a spare port rather than trusting one already running.
- Check a pure restructure by building before and after and comparing every prerendered page and the CSS, not only by tests.
- One copy of React: `package.json` `resolutions` pins `react` and `react-dom`, because Storybook's docs addon once pulled a second, newer copy ("Cannot read properties of null (reading 'useId')"). Bump both versions there when upgrading React.
- Tests that render `<App />` or a case study view mock `preloadImages` (`vi.mock`, as `App.test.tsx` does). Otherwise its idle timer outlives the test file and calls `new Image()` after jsdom is gone: Vitest fails the run on that unhandled error although every test passed, and only on a slower machine, so `yarn verify` passed here while Netlify's build of v5.2.3 failed.
